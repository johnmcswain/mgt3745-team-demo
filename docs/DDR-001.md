# DDR-001: bolt.new Specification Probe

## Task

Run FEATURES.md, alone, through bolt.new in one prompt, and record every assumption the build made that the spec did not state. The output is the list in docs/PROBE-001.md; the generated code is discarded.

## Tool and Model

bolt.new, 2026-09-28, model as reported in the bolt interface at the time of the run. Run from Priya's account, on screen for the team.

## Economic Rationale

A human reading FEATURES.md for gaps: about 1.5 hours across two members, and we would miss the gaps we share. bolt run: 10 minutes. Recording findings: 40 minutes. Net saving about 40 minutes, and the probe finds gaps a team reading its own spec cannot, which is the real reason to delegate it.

## Trust Boundary

FEATURES.md crossed to bolt.new and StackBlitz. It contains no customer data, synthetic or real, and no credentials. No GitHub connection was made. Nothing returned was committed. Accountable: Priya. TOOLS.md row added.

## Verification Performed

Priya and Leo compared each screen of the generated app against FEATURES.md, row by row, and listed every behavior with no matching row. Marcus checked the list against the build a second time. Two items the first pass missed (the currency dropdown and the customer portal) came from the second.

## Findings

Six assumptions, five of them spec gaps, all listed in PROBE-001 with the change each produced. The probe cannot tell us whether the spec is right, only whether it is complete enough that a builder would not have to guess.
